# افتقاد خورس القديس أبانوب

تطبيق بواجهة React وAPI بـ.NET 8 وقاعدة PostgreSQL. يحفظ زيارات البيت بالتاريخ، والاتصالات الأسبوعية، وتوزيع خادم لكل جروب، وتقرير تاريخ كل ولد، وإدارة الأسماء والعناوين والأرقام من داخل التطبيق.

## تشغيل محلي

المتطلبات: Docker Desktop و.NET 8 وNode.js.

1. من مجلد المشروع شغّل PostgreSQL محليًا:

   `docker run -d --name abanoub-followup-postgres -e POSTGRES_DB=choir_followup -e POSTGRES_USER=choir_app -e POSTGRES_PASSWORD=local-dev-only-password -p 127.0.0.1:55432:5432 -v abanoub_followup_pgdata:/var/lib/postgresql postgres:18`

2. انسخ `.env.example` إلى `.env`. للإعداد المحلي استخدم `DATABASE_URL=Host=127.0.0.1;Port=55432;Database=choir_followup;Username=choir_app;Password=local-dev-only-password` واجعل `APP_PASSWORD=abanoub-local` و`FRONTEND_ORIGIN=http://localhost:5174`.
3. شغّل الـAPI في نافذة Terminal:

   `dotnet run --project dotnet-api/FollowUp.Api`

4. في نافذة ثانية شغّل الواجهة:

   `cd react-app`

   `npm install`

   `npm run dev -- --host 127.0.0.1 --port 5174`

5. افتح `http://127.0.0.1:5174` وكلمة مرور الدخول المحلية `abanoub-local`.

تُنشأ جداول قاعدة البيانات تلقائيًا عند بدء الـAPI. استخدم Tab `إدارة الأسماء` لإضافة أو تعديل أو أرشفة أي اسم. قاعدة البيانات المحلية محفوظة في Docker volume.

## تنسيق وفحص التغييرات

- واجهة React: `npm --prefix react-app run format` لتنسيق الملفات، و`npm --prefix react-app run format:check` لمراجعة التنسيق.
- بناء الواجهة: `npm --prefix react-app run build`.
- تنسيق API: `dotnet format whitespace dotnet-api/FollowUp.Api/FollowUp.Api.csproj --no-restore`.
- فحص تنسيق API: `dotnet format whitespace dotnet-api/FollowUp.Api/FollowUp.Api.csproj --no-restore --verify-no-changes`.
- بناء API: `dotnet build dotnet-api/FollowUp.Api/FollowUp.Api.csproj --no-restore`.

## النشر

- **Render PostgreSQL:** استخدم قاعدة الموقع الموجودة أو قاعدة جديدة، واضبط `DATABASE_URL` داخل Render فقط. لا تنقل البيانات القديمة ولا تشغّل اختبارات على قاعدة الموقع. جداول المحادثات (`chat_conversations` و`chat_messages`) تُنشأ تلقائيًا عند بدء API دون المساس ببيانات الخورس.
- **Render API:** استخدم `render.yaml` وDockerfile الموجود. أضف `DATABASE_URL` و`APP_PASSWORD` و`FRONTEND_ORIGIN` و`AI_API_KEY` و`CHAT_SESSION_SECRET` كمتغيرات خاصة، وكذلك `KNOWLEDGE_OCR_URL` و`KNOWLEDGE_OCR_SECRET` عند تفعيل PDF. أمر التشغيل داخل الحاوية `dotnet FollowUp.Api.dll`، والمنفذ 10000.
- **Render OCR worker:** `render.yaml` يعرّف خدمة `abanoub-knowledge-ocr` من `knowledge-worker/Dockerfile` على خطة مجانية. ضع فيها `KNOWLEDGE_OCR_SECRET` (نفس قيمة API، بلا نشرها في Git) و`KNOWLEDGE_OCR_ENABLED=true`، ثم انسخ عنوانها إلى `KNOWLEDGE_OCR_URL` في خدمة API.
- **Vercel:** إعداد المستودع الحالي يبني `react-app`؛ أضف `VITE_API_URL` بعنوان API الفعلي ثم أعد البناء. لا تضع أي إعداد `AI_*` في Vercel أو في متغيرات تبدأ بـ`VITE_`.
- حدّث `FRONTEND_ORIGIN` في Render إلى عنوان Vercel الفعلي. اختبر `/health` و`/api/health` و`/api/chat/health` بعد النشر.
- بدء API يطبّق المخطط الإضافي `knowledge-schema.sql` تلقائيًا. خذ نسخة احتياطية وراجع التغييرات قبل إعادة نشره على قاعدة الموقع؛ لا يلزم تغيير سجلات الخورس القديمة.

ملفات `.env` مستثناة من Git لحماية بيانات الدخول.

## شات الكنيسة وقاعدة المعرفة

صفحة `/ask-about-ritual` عامة ولا تتطلب دخول الخدام، لكنها الآن شات كامل لأي موضوع كنسي (طقس، كتاب مقدس، قديسون، ألحان، عقيدة، تاريخ الكنيسة، حياة روحية) وليس للطقس فقط. الشات مش موجود في القائمة الرئيسية؛ بيتفتح من أيقونة القديس أبانوب اللي بتتحرك في صفحات الموقع، والمستخدم يقدر يسحب الأيقونة بالماوس أو بالإصبع ويحطها في المكان اللي يحبه، والمكان بيتحفظ ويتفتح تاني عليه بعد إعادة التحميل، والنقر من غير سحب بيفتح الشات. فتح الرابط مباشرة بيعرض صفحة تعريفية للوصول من الأيقونة. المحادثات تُحفظ على الخادم لكل جلسة، والملخص ذاكرة داخلية بتتحدث كل 4 رسائل جديدة: بيتحفظ على الخادم ويدخل مع السؤال الجديد ومع آخر الرسائل عشان الموديل يفهم إن السؤال مكمّل لنفس الحوار، لكنه مش بيتعرض أعلى الرسائل. مع قائمة المحادثات السابقة وإمكانية حذف أي محادثة. الجلسة المجهولة توقَّع لمدة 30 يومًا وتُخزن في `localStorage`، ويعيد فتح الصفحة آخر محادثة تلقائيًا. إدارة المصادر موجودة داخل **إدارة المحتوى ← قاعدة المعرفة** وتتطلب ترويسات دخول الخدام الموجودة؛ إخفاء الرابط ليس بديلًا عن الحماية في API.

الردود بلهجة مصرية بسيطة كخادم يتكلم مع ولد، وتبقى من المصادر فقط، وتظهر في الشات كرد خادم مباشر من غير ملاحظات أو إحالات ظاهرة تحت كل رسالة. الـAPI يرجع الإحالات بالنص المخزن كما هو مع اسم الكتاب والصفحة للمراجعة والتحقق من الصياغة، لكن الواجهة العامة لا تعرضها. التحيات والشكر وأسئلة التعريف تُجاب محليًا بدون استدعاء النموذج، والأسئلة القصيرة تُفهم كسؤال متابعة على سياق نفس المحادثة (يُرسل الملخص وآخر الرسائل مع الطلب).

أضف إلى `.env` في جذر المشروع:

```dotenv
AI_PROVIDER=gemini
AI_CHAT_MODEL=gemini-3.1-flash-lite
AI_EMBEDDING_MODEL=gemini-embedding-001
AI_EMBEDDING_DIMENSIONS=768
AI_API_KEY=
CHAT_SESSION_SECRET=
CHAT_SESSION_HOURLY_LIMIT_ASK=12
CHAT_IP_HOURLY_LIMIT=30
CHAT_GLOBAL_DAILY_LIMIT=200
KNOWLEDGE_BOOTSTRAP_PATH=
KNOWLEDGE_OCR_URL=
KNOWLEDGE_OCR_SECRET=
KNOWLEDGE_OCR_BATCH_PAGES=12
KNOWLEDGE_OCR_TIMEOUT_SECONDS=110
```

ضع المفتاح والسر محليًا بدون نشرهما. إن لم تضبط سر الجلسة يستخدم الخادم كلمة دخول الخدمة لتوقيع الجلسات؛ يفضل سر مستقل طويل على Render. النموذج الافتراضي اقتصادي وتم التحقق من الوصول إليه؛ الأسعار والحصص لدى المزود قابلة للتغيير. يمكن ضبط `AI_ADVANCED_CHAT_MODEL` اختياريًا، ولا يستخدم إلا عند إرسال `advanced=true`؛ الافتراضي هو النموذج الاقتصادي نفسه. تغيير نموذج/أبعاد التضمين يتطلب إعادة فهرسة كل مصدر؛ المقاطع ذات ملف تضمين مختلف لا تدخل البحث. مهايئ Gemini الحالي يدعم تضمينات النص `gemini-embedding-001`؛ مزود آخر ينفذ `IAiProvider` و`IKnowledgeVectorStore` بدل تغيير مسار الأسئلة.

النصوص المسترجعة والأسئلة ترسل إلى Gemini لتوليد التضمينات واختيار الأدلة. المحتوى المرفوع مملوك لك، وملاحظة الإذن اختيارية: عند تركها فارغة يُسجَّل تلقائيًا أن المصدر مملوك لإدارة الموقع. قد تُستخدم بيانات الطبقة المجانية لتحسين منتجات Google وفق شروط المزود، لذلك لا ترفع بيانات شخصية.

### استيراد الكتاب الأول

1. لاختبار محلي فقط، اضبط `DATABASE_URL` صراحةً على قاعدة محلية منفصلة، و`APP_PASSWORD` محلية، ولا تعتمد على قيمة قاعدة الموقع في `.env`.
2. اجعل `KNOWLEDGE_BOOTSTRAP_PATH` المسار الكامل لملف JSONL المقدم، أو شغّل بيئة Development مع نسخة الملف في `output`. يحتفظ النظام بترقيم الصفحات الوارد في الملف، وليس ترقيمًا مطبوعًا مفترضًا.
3. شغّل API ثم افتح قاعدة المعرفة لمتابعة الاستخراج والتضمين. عملية الاستيراد الأولي تمنع التكرار باستخدام بصمة الملف. فعّل المصدر بعد اكتمال فهرسته.
4. في Render ارفع JSONL أو TXT من قاعدة المعرفة؛ يضاف تلقائيًا إلى طابور الفهرسة، ويمكن إعادة الفهرسة من الزر عند الحاجة. الكتاب ليس مضمنًا في صورة Docker أو Git؛ لا تعتمد على مجلد `output` المحلي بعد النشر.

الملفات تحفظ في PostgreSQL والمهام لها طابور دائم؛ إعادة تشغيل Render لا تفقد الرفع أو المهمة. حجم الرفع الأقصى 20MB. المطلوب عند الرفع هو الملف والتصنيف فقط: العنوان اختياري ويُؤخذ من اسم الملف عند تركه فارغًا، والمؤلف وملاحظة الإذن اختياريان أيضًا. TXT يفهم العلامة `===== صفحة 1 =====`؛ TXT بلا علامات يعامل كصفحة واحدة. JSONL يتطلب `source` و`page` و`chunk` و`text`؛ يعاد تقسيم النص داخل كل صفحة مع تداخل قصير، وقد تكون الصفحات القصيرة أقل من 800 حرف. لن يصبح مصدر بفشل استخراج صفحات جاهزًا للإجابات قبل معالجة المشكلة وإعادة فهرسته. إعادة الفهرسة تستأنف من حيث توقفت: الصفحات والمقاطع المكتملة تبقى كما هي، فلا تستهلك حصة المزود مرة أخرى إلا في الأجزاء الناقصة.

### البحث والتحقق

يعاد ترتيب أفضل 24 نتيجة من التضمينات بمطابقة مصطلحات السؤال، وتستخدم الإجابة أفضل 6 مقاطع فقط. يختار النموذج أجزاء النص التي تجيب عن السؤال، ثم يعيد كتابة المعلومة بصياغته الخاصة دون نسخ المقاطع حرفيًا؛ والـAPI يرجع مع الإجابة إحالات بالنص المخزن كما هو مع اسم الكتاب والصفحة للمراجعة، لكن الشات العام يعرض الرد وحده. الإجابة إعادة صياغة للمقاطع المختارة فقط: أي معلومة أو تفصيلة أو مثال أو رقم خارجها يرفض الإجابة كلها. لا توجد إجابات من معرفة النموذج العامة ولا من الإنترنت. عند غياب الدليل أو رفض الإجابة: **المعلومة غير موجودة في المصادر المتاحة حاليًا.** تعطل المزود أو اقتباس غير قابل للتحقق يعطي خطأ قابلًا لإعادة المحاولة وليس جواب الغياب. ذاكرة الأسئلة/الإجابات قصيرة ومحدودة ولا تسجل محتوى الأسئلة في سجلات التطبيق؛ تغيير المصادر أو تعطيلها يلغي أهلية الإجابات المخزنة. درجة الثقة تشابه استرجاع وليست ضمانًا عقائديًا.

يعمل البحث افتراضيًا بمقارنة cosine فعلية للتضمينات المخزنة في `real[]`. إذا كان pgvector مثبتًا في قاعدة البيانات يستخدم مسار المتجهات الاختياري؛ لا يتطلب التطبيق صلاحية تثبيت امتداد. يمكن لمسؤول قاعدة مصرح له تثبيت `CREATE EXTENSION IF NOT EXISTS vector` ثم إعادة تشغيل API وإعادة الفهرسة. لا تشغل ذلك على الإنتاج دون مراجعة؛ البحث البديل يعمل بدونه. الفحص الدقيق مناسب للمكتبة الصغيرة؛ عند توسعها يمكن استبدال `IKnowledgeVectorStore` بقاعدة متجهات خارجية.

الحصص دائمة ومشتركة بين نسخ API: لكل جلسة/IP في الساعة وللموقع يوميًا. يحصل العميل على جلسة موقعة من `/api/chat/session` ويستخدم `X-Chat-Session`، ولا يحتاج Cookie طرف ثالث بين Render وVercel. الحد 1000 حرف للسؤال، وHTML مرفوض. اضبط `CHAT_TRUSTED_PROXIES` فقط بعناوين الوكلاء الموثوقين الفعلية (مفصولة بفواصل) بعد التحقق من إعداد الاستضافة؛ لا تثق بترويسة `X-Forwarded-For` من أي عميل. بدون إعداد الوكيل قد تشترك طلبات Render في حصة IP واحدة، وهو أكثر تحفظًا لكنه قد يحد الاستخدام.

### PDF وOCR

رفع أي PDF يعمل تلقائيًا: الصفحات النصية تُستخرج مباشرة بـPyMuPDF، والصفحات التي بلا نص تُصوَّر وتُقرأ بـTesseract (ara+eng) داخل العامل المنفصل، ثم تُقسم وتُضمَّن كالمعتاد. لا حاجة لخطوة يدوية لكل ملف. شغّل العامل محليًا:

```sh
docker build -t choir-knowledge-worker ./knowledge-worker
docker run --rm --init --read-only --cap-drop=ALL --security-opt=no-new-privileges --memory=1g --cpus=1 --pids-limit=32 --tmpfs /tmp:rw,noexec,nosuid,size=256m,mode=1777 -p 127.0.0.1:8090:8090 -e KNOWLEDGE_OCR_SECRET -e KNOWLEDGE_OCR_ENABLED=true choir-knowledge-worker
```

صدّر `KNOWLEDGE_OCR_SECRET` في بيئة نافذة Docker أولًا؛ الأمر يمرر هذا السر وحده ولا يمرر ملف إعداد API كله للعامل. اضبط `KNOWLEDGE_OCR_URL` على عنوان العامل الفعلي و`KNOWLEDGE_OCR_SECRET` على سر مستقل طويل في العامل وAPI. عند نشره استخدم خدمة Docker خاصة منفصلة وحدود ذاكرة مناسبة؛ لا تعرّضه للعامة بلا سر.

- API يطلب الصفحات على دفعات بحجم `KNOWLEDGE_OCR_BATCH_PAGES` (12 افتراضيًا، بين 3 و60) ولمهلة لكل دفعة `KNOWLEDGE_OCR_TIMEOUT_SECONDS` (110 افتراضيًا، بين 20 و180). هذا يمنع تعليق الملفات الكبيرة في طلب واحد ويعيد المحاولة تلقائيًا عند تعطل العامل أو انتهاء المهلة أو 429/502/503/504.
- العامل يعالج النطاق المطلوب فقط، وإن طلب API نهاية أكبر من عدد صفحات الملف يقصّها العامل للعدد الفعلي. الصفحات الناقصة تُعلَّم فاشلة، ويظهر المصدر «فشل جزئي» أو «يتطلب OCR» ولا يصبح جاهزًا للإجابة.
- بدون عامل تظهر حالة **يتطلب OCR** بدل الإيهام بالفهرسة. استخراج PDF النصي وOCR العربي يعملان في عملية معزولة بحدود وقت وحجم وصفحات، ويعرضان الصفحات الفاشلة.
- على Render استخدم الخدمة `abanoub-knowledge-ocr` المعرَّفة في `render.yaml` (خطة مجانية تنام بعد خمول). بعد خمول طويل قد يستغرق أول طلب نحو دقيقة، والدفعات تعيد المحاولة تلقائيًا؛ لو استمر الفشل أعد الفهرسة من الزر. اضبط `KNOWLEDGE_OCR_URL` في API على عنوان الخدمة، ونفس `KNOWLEDGE_OCR_SECRET` في API والعامل، و`KNOWLEDGE_OCR_ENABLED=true` في العامل.

### عقود API

- `POST /api/chat/session` → `{sessionToken}` صالح 30 يومًا.
- `POST /api/chat/ask` مع `X-Chat-Session` وجسم `{question,conversationId?,advanced?}` → `{answer,sources:[{title,page,snippet}],confidence,conversationId,summary}`. تمرير `conversationId` يكمل نفس المحادثة، و`summary` هو ذاكرة الملخص المحدَّثة بعد 4 رسائل جديدة أو الأخير كما هو؛ الواجهة بتستخدمها كسياق للموديل ومش بتعرضها.
- `GET /api/chat/conversations` → `{conversations:[{conversationId,title,summary,messageCount,updatedAt}]}` (آخر 30 محادثة للجلسة).
- `GET /api/chat/conversations/{id}` → `{conversation:{conversationId,title,summary,messages}}` (آخر 40 رسالة)، و`DELETE` يحذفها نهائيًا. كلها تعيد `401 session_required` بدون جلسة، و`404 not_found` لمحادثة جلسة أخرى.
- `GET /api/chat/health`: اتصال القاعدة ووجود إعداد المزود؛ ليس اختبار توليد حيًا ولا تأكيدًا لرصيد المزود.
- إدارة محمية: `GET/POST /api/knowledge/sources`، `PUT/DELETE /api/knowledge/sources/{id}`، `POST /api/knowledge/sources/{id}/ingest`، `GET /api/knowledge/chunks/{sourceId}?offset=0&limit=50`.
- إنشاء المصدر multipart، والتعديل JSON. الأخطاء تعيد رسالة مناسبة، وأخطاء الشات تحتوي `code` و`message`.

اختبارات التحقق من الاقتباسات والجلسات: `dotnet run --project dotnet-api/FollowUp.Api.Tests`. وبعد تشغيل API محلي على المنفذ 5089 وفهرسة الكتاب: `node tests/chat.integration.mjs`؛ يمكن ضبط `TEST_API_URL` و`TEST_APP_PASSWORD` محليًا، ويرفض الاختبار عنوان إنتاج. فحوص الحماية: `node tests/chat-security.integration.mjs` مع حد جلسة 12 وحد IP محلي 100؛ يعطّل الكتاب مؤقتًا ويعيد تفعيله في `finally`، ويجب أن تكون المصادر الأخرى غير مفعلة. يمكن تمرير `TEST_FAILURE_API_URL` لنسخة API محلية مستقلة بنموذج محادثة غير موجود لاختبار خطأ المزود.

تحقق حيًا بعد فهرسة المصدر من «ما هي رتب الشمامسة؟»، «ما معنى الإبصالتس؟»، «ما الزيوت المستخدمة في المعمودية؟»، «ما وظيفة الإيبوذياكون؟»، وسؤال غير موجود. راجع الاقتباس ورقم الصفحة مقابل المصدر، ثم جرّب تعطيل المصدر وتعطل المزود وواجهة الهاتف 390/412px. البناء وحده لا يثبت صحة الإجابات أو OCR. لاختبار OCR محليًا: شغّل العامل بـ`KNOWLEDGE_OCR_ENABLED=true` مع Tesseract بيانات `ara` و`eng`، ثم ارفع PDF نصي متعدد الصفحات وآخر ممسوح الصور وتأكد أن الأول يستخرج نصه دون OCR وأن الثاني يُقرأ ويُفهرس، وافتح المحادثة بعد إعادة تحميل الصفحة للتأكد من حفظ الملخص والسجل.
